1. Project Purpose & Problem Statement

In traditional institutions (colleges, corporations, government bodies), verifying certificates, legal deeds, and degrees involves slow manual phone calls, registry lookups, or third-party paid verification services. Furthermore, physical documents and regular digital PDFs are vulnerable to unauthorized editing, Photoshop alterations, and forgery.

The Solution: Cryptographic "Proof-of-Existence" (PoE)
This decentralized application (DApp) anchors a cryptographic fingerprint (SHA-256 hash) of any document onto an immutable Ethereum smart contract together with an authoritative timestamp and issuer wallet address. Anyone worldwide can instantly verify if a given file is authentic or tampered with in under 1 second.

3. Which Blockchain is Used & Why is it 100% Free?

Which Blockchain?

The project runs on an Ethereum-compatible EVM (Ethereum Virtual Machine) blockchain hosted locally using the industry-standard Hardhat Network.

  • RPC Endpoint: http://127.0.0.1:8545
  • Chain ID: 31337 (standard local Hardhat test network ID)
  • EVM Version: Paris / London compatibility

Why is it 100% Free? (Zero Gas Fees & Zero Cloud Costs)

1. Local Node Simulation: Instead of deploying to Ethereum Mainnet (which requires real USD/ETH for gas fees), Hardhat creates a private, full-featured simulated Ethereum blockchain directly in your computer's RAM.

2. Pre-Funded Test Wallets: Hardhat automatically creates 20 pre-funded test accounts, each initialized with 10,000 test ETH (simulated money for transaction gas fees).

3. Read Calls Cost 0 Gas: The verifyDocument() function is marked as a view function in Solidity. In Ethereum, querying a view function does NOT change state and therefore costs exactly 0 ETH!

4. How It Works Step-by-Step: The Complete Workflow

Step A: Notarization Workflow (Recording Proof-of-Existence)

  1. File Selected: User drops any document (PDF, PNG, DOCX) into the browser dropzone.
  2. Client-Side SHA-256 Hashing: The native browser window.crypto.subtle.digest("SHA-256", arrayBuffer) processes the binary file into a unique 256-bit hexadecimal digest (prefixed with 0x, resulting in a 66-character bytes32 string).
    Crucial Security Note: The document itself is NEVER uploaded across the internet. Only its hash is shared.
  3. Transaction Submission: User clicks "Notarize on Blockchain". Ethers.js invokes the smart contract method: 
    notarizeDocument(bytes32 docHash, string memory docName)
  4. Wallet Signature: MetaMask (or the built-in demo wallet) signs the transaction using the user's private key and broadcasts it to the local node.
  5. Blockchain State Mutation: The smart contract validates that the hash hasn't been registered yet, saves the block timestamp (block.timestamp), caller address (msg.sender), and title into its storage mapping, and emits a DocumentNotarized event.

Step B: Verification Workflow (Authenticity vs Tampering)

  1. Target File Uploaded: The examiner or verifier uploads the document they want to inspect.
  2. Recalculate Hash: The browser calculates the SHA-256 digest of the uploaded file on the spot.
  3. Query Smart Contract: Ethers.js invokes the read-only view method: 
    (bool exists, uint256 timestamp, string memory docName, address notarizedBy) = verifyDocument(docHash);
  4. Evaluation:
    • If exists == true: Displays green '✅ Authentic Document' with the exact certification timestamp and signer address.
    • If exists == false: Displays red '❌ Unverified / Modified Document'. Even if a single character or punctuation mark was changed, the cryptographic Avalanche Effect alters the hash completely, exposing any tampering immediately!

5. How Data is Stored: Why Hash instead of the Full File?

A frequent question from professors is: "Where is the actual PDF stored on the blockchain?"

The Golden Rule of Blockchain Engineering:
Blockchains are designed for consensus and state verification, NOT large binary file storage.
  • A typical PDF is 2 MB to 20 MB. Storing 1 MB on public Ethereum costs over $10,000 in gas fees!
  • Storing a SHA-256 hash requires only 32 bytes (`bytes32` in Solidity).
  • Because SHA-256 is mathematically collision-resistant, a 32-byte hash proves the integrity of a 500-page document with 100% cryptographic certainty!

Solidity Storage Structure:

struct Record {
    bytes32 docHash;        // 32-byte cryptographic digest
    string docName;         // Human-readable title
    uint256 timestamp;      // UNIX timestamp (seconds since 1970)
    address notarizedBy;    // Ethereum public address of signer
    bool exists;            // Boolean existence flag
}

mapping(bytes32 => Record) private documents;

7. Top 5 Viva / Oral Exam Questions & Answers

Q1: What happens if an attacker modifies just one space or digit in the document?
A: Due to the cryptographic Avalanche Effect in SHA-256, changing even a single bit in the input produces a completely unrecognizable hash. When queried, the smart contract returns exists = false, immediately triggering the red Unverified status.
Q2: Can someone notarize the same document twice with a different name?
A: No. The smart contract contains the check: require(!documents[docHash].exists, "Document has already been notarized");. The primary key is the document hash, ensuring each document has a unique, first-timestamped record.
Q3: Is the document content exposed publicly on the blockchain?
A: No. Only the cryptographic hash (a one-way mathematical digest) is stored. It is mathematically impossible to reverse-engineer or extract the original document content from the SHA-256 hash.
Q4: Why does verifying a document not require paying gas fees?
A: Verification queries a Solidity view function. In Ethereum, view functions only read data from the local node's copy of the blockchain and do not create or alter any state, so no gas or wallet transaction is needed.
Q5: Can someone alter or delete an already notarized document record?
A: No. Blockchains are append-only distributed ledgers. The smart contract intentionally does not include any delete or update methods, making the notarization permanently immutable.
